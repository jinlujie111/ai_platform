# AI 平台建设计划（四阶段）

> 文档版本：v1.0  
> 更新日期：2026-07-27  
> 适用范围：`ai_platform` 现有工程演进，目标对标「AI Gateway → MCP Tool Center → Agent Runtime → LLMOps」  
> 定位：内部增强型 MVP / 可试点原型 → 可运营的金融分析 AI 平台

---

## 1. 背景与目标

### 1.1 现状一句话

当前平台已具备：多模型聊天、知识库 RAG、数据源与流水线、登录注册、个人配置落 MySQL、飞书简单对话、基础 Agent/MCP/Skill 配置。整体约为 **增强型内部 MVP（约 6/10）**，可试点，尚未达到生产级隔离与可运营能力。

### 1.2 建设目标

按以下四阶段建成可运营架构：

| 阶段 | 名称 | 目标一句话 |
|------|------|------------|
| P1 | AI Gateway | 统一接入多厂商模型，具备路由、认证、限流、成本统计 |
| P2 | MCP Tool Center | 将东方财富、AkShare、Python、MySQL、新闻等封装为标准 MCP 工具 |
| P3 | Agent Runtime | 行业分析 / 选股 / 研报 / 新闻等多 Agent 协作 |
| P4 | LLMOps + Observability | Prompt 管理、评测、日志、监控、成本分析、模型版本管理 |

### 1.3 原则

1. **演进现有工程，不推倒重来**：在 `ai_platform` 上收口与升级。  
2. **模型算力外置**：GPT / Claude / Qwen / DeepSeek 走云端 API；本机做编排与研发。  
3. **先安全隔离，再能力扩展**：全 API 鉴权与资源归属优先于新功能。  
4. **证据优先**：金融结论必须带来源、时间戳、口径说明，抑制幻觉。  
5. **观测前置**：从 P1 开始埋点，不要等 P4 才补日志与成本。

## 3. 本机硬件评估

### 3.1 当前环境（建设机）

| 项 | 规格 |
|----|------|
| CPU | Intel Core i7-1255U（10 核 / 12 线程） |
| 内存 | 16 GB |
| 显卡 | Intel Iris Xe + NVIDIA GeForce MX570 A（约 2GB 显存） |
| 角色定位 | **研发与编排主机**，非本地大模型算力中心 |

### 3.2 结论

| 能力 | 是否支持 |
|------|----------|
| 平台开发、MySQL、FastAPI、前端 | ✅ 支持 |
| AI Gateway / MCP / Agent 编排（云端模型） | ✅ 支持 |
| 轻量 Embedding、小并发 MCP | ⚠️ 可用，需限并发 |
| 本机常驻 7B+ Chat 大模型、高并发本地推理 | ❌ 不建议 |
| 多人正式试点 / 重评测 | ⚠️ 建议升内存或上云主机 |

### 3.3 升级建议（按优先级）

1. 云模型额度（DeepSeek / 通义等性价比优先）  
2. 内存升至 **32 GB**（多 Agent + 本机服务更稳）  
3. 试点环境使用云主机；需要本地大模型时再考虑 **16GB+ 显存** GPU

## 4. 阶段 0：地基加固（先于四阶段）

**周期：** 2–3 周  
**目的：** 避免 Gateway / Agent 建在不安全的共享沙箱上。

### 4.1 工作项

- [ ] 业务 API 全面鉴权（chat / knowledge / datasource / pipeline 等）
- [ ] 资源表增加归属字段（如 `owner_id` / `tenant_id`）
- [ ] 数据源密码、API Key 加密存储
- [ ] 统一 `request_id` / `trace_id` 与结构化日志
- [ ] 默认管理员密码强制修改策略
- [ ] 基础健康检查接口（`/health`、`/ready`）

### 4.2 验收标准

- 无 Token 无法调用业务 API  
- 用户 A 不可读写用户 B 的知识库 / 会话 / 私有配置  
- 密钥不以明文出现在日志与接口回包中

## 5. 阶段 1：AI Gateway

**周期：** 6–8 周  
**目标：** 所有模型调用只经 Gateway，业务侧只认逻辑 `model_id`。

### 5.1 能力清单

| 能力 | 说明 |
|------|------|
| 统一接入 | OpenAI 兼容、Anthropic、通义、DeepSeek 等适配器 |
| 模型路由 | 按任务类型 / 成本 / 延迟 / 可用性选择模型 |
| 认证 | 平台登录态 + 对外 API Key |
| 限流 | 用户 / Key / 模型三维限流 |
| 成本统计 | 按用户、模型、Agent、会话记账 Token 与费用 |

### 5.2 建议数据表

- `model_providers`：厂商与连接配置  
- `model_definitions`：逻辑模型与上游映射  
- `model_routes`：路由策略与版本  
- `platform_api_keys`：对外调用凭证  
- `usage_ledger`：用量与成本流水  
- `rate_limit_buckets`：限额状态（可用 Redis 替代）

### 5.3 里程碑

| 里程碑 | 内容 | 建议周次 |
|--------|------|----------|
| M1.1 | 适配器层 + 统一 `POST /v1/chat/completions` 形态出口 | W1–W2 |
| M1.2 | 路由策略（默认 / 便宜 / 高质量） | W3–W4 |
| M1.3 | API Key + 限流 | W5–W6 |
| M1.4 | `usage_ledger` 与费用报表 | W7–W8 |

### 5.4 验收标准

- 业务代码不再直接持有多套厂商调用逻辑  
- 可按人 / 按模型导出日费用  
- 超限返回明确 429，且可配置  

### 5.5 本机可行性

完全可行（出网 HTTP 调用）。可选引入本机 Redis；初期可用 MySQL 实现简单限额。

## 6. 阶段 2：MCP Tool Center

**周期：** 6–8 周  
**目标：** 金融与数据能力标准化为 MCP，可被 Agent 发现与调用。  
**任务拆解：** 详见 [`docs/MCP_TOOL_CENTER_TASK_BREAKDOWN.md`](./MCP_TOOL_CENTER_TASK_BREAKDOWN.md)（MCP-0～MCP-4）

### 6.1 服务拆分

| MCP 服务 | 职责 | 数据源示例 |
|----------|------|------------|
| `mcp-market` | 行情、资金流、K 线 | 东方财富公开接口 / AkShare |
| `mcp-fundamentals` | 财报、公告、研报元数据 | AkShare / 公告源 |
| `mcp-news` | 新闻检索与摘要素材 | 新闻源 / AkShare 资讯 |
| `mcp-sql` | 只读 SQL | 现有数据源体系 |
| `mcp-python` | 受限代码执行 | Docker / 沙箱进程（禁止裸跑本机） |

### 6.2 工具规范（强制）

每个 Tool 响应至少包含：

- `source`：数据来源  
- `as_of`：数据时点  
- `disclaimer`：口径 / 延时说明  
- 结构化错误（不抛垮连接）

并落地：

- 分级 TTL 缓存（行情短、财报长）  
- 并发与频率限制  
- 股票代码与日期规范化  

### 6.3 里程碑

| 里程碑 | 内容 | 建议周次 |
|--------|------|----------|
| M2.1 | `mcp-market` + `mcp-sql` 可用 | W1–W3 |
| M2.2 | `mcp-fundamentals` + `mcp-news` | W4–W6 |
| M2.3 | `mcp-python` 沙箱 + 工具注册中心 | W7–W8 |

### 6.4 验收标准

- Agent 一次对话可完成「某票行情 + 财报摘要」，并带来源  
- Python 工具无法读写宿主机敏感目录  
- 工具失败可重试 / 降级，不拖垮 Agent 会话  

### 6.5 本机可行性

开发联调可行。全市场拉取需限并发 + 缓存。公开行情多为延时数据，**不得宣称实盘交易级**。

### 6.6 合规提醒

- 数据版权与展示授权需法务确认  
- 对外输出加投资风险免责声明  
- 不提供自动下单 / 交易执行能力（本计划范围外）

## 7. 阶段 3：Agent Runtime

**周期：** 8–10 周  
**目标：** 从「单 Agent + 工具」升级为「多 Agent 协作流水线」。

### 7.1 Agent 角色

| Agent | 职责 | 主要依赖 |
|-------|------|----------|
| News Agent | 舆情与事件整理 | `mcp-news` |
| Industry Agent | 行业对比与趋势 | market + fundamentals |
| Stock Pick Agent | 筛选、排序、候选池 | market + sql |
| Research Agent | 结构化研报产出 | 全工具 + 知识库 |
| Supervisor | 拆解任务、调度、汇总、质检 | 调用子 Agent |

### 7.2 运行时能力

- [ ] 任务图 / 状态机（顺序、并行、失败重试）  
- [ ] 共享工作区（中间结论落 MySQL）  
- [ ] 引用与反幻觉校验（Tool 证据链）  
- [ ] 人工审批节点（高风险结论）  
- [ ] 与 P1 Gateway 绑定（按 Agent 记账）  

### 7.3 里程碑

| 里程碑 | 内容 | 建议周次 |
|--------|------|----------|
| M3.1 | Supervisor + 2 子 Agent（News + Industry）跑通 | W1–W3 |
| M3.2 | 接入 Stock Pick + Research | W4–W7 |
| M3.3 | 共享工作区、质检、审批、报告模板 | W8–W10 |

### 7.4 验收标准

输入：「分析某某行业并给出 5 只候选标的」  
输出：多 Agent 链路可追溯 + 带来源的结构化报告。

### 7.5 本机可行性

编排可行。默认小并发（2–3）；16GB 机器避免同时开太多本地重任务。

## 8. 阶段 4：LLMOps + Observability

**周期：** 持续建设，首期 6 周；并从 P1 开始埋点。  
**目标：** 可评测、可观测、可回滚、可算账。

### 8.1 模块

| 模块 | 最小可行（MVP） |
|------|-----------------|
| Prompt 管理 | Prompt 表 + 版本 + 灰度 |
| 效果评测 | 固定题集 + 人工/自动打分 + 回归 |
| 日志 | 请求 / 工具 / Agent 全链路 `trace_id` |
| 监控 | 延迟、错误率、工具失败率、队列积压 |
| 成本分析 | 对接 `usage_ledger` 看板 |
| 模型版本 | `model_id` + 路由版本，支持回滚 |

### 8.2 建议技术选型（轻量）

- 日志与链路：结构化日志 + OpenTelemetry（可选）  
- 指标：Prometheus + Grafana（可后置）  
- 存储：评测集与跑批结果进 MySQL  
- 重评测：夜间任务或云端 CI  

### 8.3 里程碑

| 里程碑 | 内容 |
|--------|------|
| M4.1 | 全链路 trace + 基础错误看板 |
| M4.2 | Prompt / 模型版本管理 |
| M4.3 | 评测集 v1 + 成本看板 |
| M4.4 | 回归门禁（核心链路不通过禁止发布） |

### 8.4 验收标准

- 任意一次失败会话可按 `trace_id` 还原  
- 可对比两个 Prompt/模型版本的效果与成本  
- 核心题集回归可自动化执行

## 11. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 核心 API 未鉴权导致数据串用 | 高 | P0 优先完成 |
| 金融数据版权与合规 | 高 | 法务确认；免责声明；不做交易执行 |
| Python MCP 变成远程代码执行 | 高 | 强制沙箱 / Docker |
| Agent 幻觉导致错误投研结论 | 高 | Tool 证据链 + 质检 Agent + 人工审批 |
| 过早上过多 Agent | 中 | 先 Supervisor + 2 子 Agent |
| 本机当生产服务器 | 中 | 开发用本机，试点上云 |
| 公开行情延时被误用为实盘 | 中 | UI/报告明确标注延时口径 |
| 范围膨胀导致长期无法交付 | 中 | 每阶段独立验收，不允许跳过 P0 |

## 12. 成功标准（平台级）

满足以下即视为「达到目标程度」的可对外试点版本：

1. **统一出口**：全部模型调用经 AI Gateway，可路由、可限流、可计费。  
2. **工具中台**：行情 / 财报 / 新闻 / SQL / 沙箱 Python 均可被 MCP 调用。  
3. **多 Agent**：至少 1 个 Supervisor + 4 类分析 Agent 可协作产出带来源报告。  
4. **可运营**：具备 Prompt/模型版本、基础评测、链路日志与成本看板。  
5. **可安全试点**：鉴权、隔离、密钥加密、审计字段齐全。
